## Official references

- [Meta Page Public Content Access](https://developers.facebook.com/docs/features-reference/page-public-content-access/) and [Instagram Business Discovery](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-facebook-login/business-discovery/). Meta documentation returned rate-limited responses in this environment; current app-specific permissions must be verified in Meta App Review before enabling anything beyond restricted status. Connectivity tests do not mark the integration generally approved.
- [Places API policies](https://developers.google.com/maps/documentation/places/web-service/policies) and [Google Maps Platform terms](https://cloud.google.com/maps-platform/terms). No caching or exporting protected Google fields into an independent lead database. If a future UI displays actual Places content, add the required Google logo/attributions and review storage rules first. The current adapter only returns IDs and displays no place details.
- [Overture Places guide](https://docs.overturemaps.org/guides/places/), [schema](https://docs.overturemaps.org/schema/reference/places/place/), [operating status](https://docs.overturemaps.org/schema/reference/places/types/operating_status/), [DuckDB](https://docs.overturemaps.org/getting-data/duckdb/), [per-source attribution](https://docs.overturemaps.org/attribution/). Pin and review releases; an `open` clue is not a business verification. Places upstream licenses vary. Preserve Apache notices and other per-source requirements; do not apply OSM attribution/share-alike assumptions to all Places records.
- [Brave API](https://brave.com/search/api/) and [web search contract](https://api-dashboard.search.brave.com/api-reference/web/search/get). Storage rights depend on plan; the search API does not grant third-party website content rights.
- [Hunter API reference](https://hunter.io/api-documentation). `valid` is detailed status; `result` is deprecated. `verification.date` can be older than the request. `accept_all`, `block` and `claimed_email` are handled conservatively. Pending 202 is unverified, not success.
- [Canada federal data services](https://ised-isde.canada.ca/site/corporations-canada/en/data-services) and [dataset catalog](https://open.canada.ca/data/en/dataset/0032ce54-c5dd-4b66-99a0-320a7b5e99f2). Federal coverage differs from provincial/state feeds.
- [GeoNames downloads/licence](https://download.geonames.org/export/dump/), [US Census Gazetteer](https://www.census.gov/geographies/reference-files/time-series/geo/gazetteer-files.html). Current shipped city importer supports GeoNames; Census-specific parsing is not implemented.

## Licensing audit procedure

1. Administrator reviews the exact source/record license, commercial reuse, storage/export and attribution conditions. An import checkbox records an attestation, not an independent legal certification.
2. Each batch keeps digest, source URL, license, attribution and count. Imported emails require their own public evidence URL; source flags may not inject a verifier result.
3. Review unknown or mixed upstream Overture licenses before import. A source registry card alone grants no rights. Never import protected Google/Meta/Yelp results as generic CSV.
4. Worker contact findings keep their actual page URL and reviewed host policy. Do not treat one contact's export rights as permission for all other fields.
5. Export rechecks business and contact field rights, freshness, suppression and fixture flags. Restricted sources never run through the discovery registry.
6. Refresh the official policy references and app-specific approvals before production use; retain agreement/notice evidence outside public Git history.
